# Berlioz Admin 0.14.1

Unreleased. Maintenance release of the 0.14 line, at `org.pageseeder.berlioz:pso-bzadmin:0.14.1`.
It still requires Berlioz 0.14.5. Admin operations moved to an internal API, so check
[Requirements and upgrade](#requirements-and-upgrade) if the host or its proxy refers to admin URLs.

## Changes

### Access and security

- **Fallback login throttling.** Password checks are limited by client and overall, and excess
  requests receive `429 Too Many Requests` with `Retry-After`. Administrators already signed in are not
  affected. This addresses a [known limitation of 0.14.0](0.14.0.md#known-limitations). See
  [the fallback login](../access.md#c-the-fallback-login).
- **Development proxies.** Same-origin checks for operations prefer `Sec-Fetch-Site`, falling back to
  `Origin` for browsers that do not send it, so operations work behind a local development proxy. A
  development-only `local-proxy` setting allows the fallback login through a proxy on the same machine,
  and the log explains proxy-related refusals. See [local development proxies](../access.md#local-development-proxies).
- **Container challenges.** With container BASIC authentication, declare an
  [error page for 401](../access.md#error-page-for-401) so that requests other than GET receive the
  container's challenge. The cause is in Berlioz's error handling and remains a known limitation.

### Integration

- **Berlioz mapped by prefix.** Operations and live updates now work when Berlioz is mapped to `/html/*`
  and `/xml/*`, using `/xml/bzadmin/api/`. See [Berlioz mapped by prefix](../access.md#berlioz-mapped-by-prefix).
- **Startup check.** The overlay warns on the console, with the prefix `[BERLIOZ_INIT] WARNING`, when
  `AdminFilter` is missing or does not cover the admin services, or when Berlioz has an HTML mapping
  without the matching XML one. It registers nothing.
- **XML stylesheet.** The overlay provides `xslt/xml/bzadmin.xsl`, which removes the Berlioz header from
  XML responses. A host can override it, as for HTML. See [stylesheet overrides](../guides/configuration.md#stylesheet-overrides).
<!-- TODO before release: confirm whether this removes the kickstart fallback-stylesheet warning listed in 0.14.0. -->
- **Filter mapping.** The documented `AdminFilter` mapping has no dispatcher elements, so it applies to
  direct requests only (`REQUEST`). Add `FORWARD` or `ERROR` only when the host forwards to admin URLs or
  uses them as error pages. See [map the filter](../access.md#1-map-the-filter).

### Interface

- **Logs.** The Recent view lists events most recent first, with a button to reload them.
- **Config.** Berlioz options configured with their default value are marked "same as default".
- **System.** Rows for known memory pools (heap generations, Metaspace, code cache…) explain what their
  usage means, for HotSpot from Java 11 to 25.

## Requirements and upgrade

Requirements are unchanged from [0.14.0](0.14.0.md#requirements-and-upgrade): Java 11, Berlioz 0.14.5
or later in the 0.14 line, a Servlet 4 (`javax.servlet`) container and a host-provided XSLT 2.0 processor.

From 0.14.0, change the overlay dependency to `0.14.1` and redeploy with exactly one overlay JAR. The
versioned JavaScript and CSS filenames change to `bzadmin-0.14.1.min.js` and `bzadmin-0.14.1.min.css`.
Access configuration and Java integration APIs are unchanged.

**Admin operations moved to `/bzadmin/api/`.** The admin pages use the new URLs, so no change is needed
when the host constrains `/bzadmin/*` as documented. Update any rule or tool that names an old URL, such
as a proxy or firewall allowlist, a script that calls an operation, or alerting on the audit log, whose
lines now show the new paths. The old URLs return 404.

| 0.14.0 | 0.14.1 |
| --- | --- |
| `POST /bzadmin/<operation>`, such as `/bzadmin/cache/clear` | `POST /bzadmin/api/<operation>`, such as `/bzadmin/api/cache/clear` |
| `GET /bzadmin/system/cpu/sample`, `/bzadmin/system/runtime/sample` | `GET /bzadmin/api/system/cpu`, `/bzadmin/api/system/runtime` |
| `GET /bzadmin/cache/info/sample` | `GET /bzadmin/api/cache/info` |
| `GET /bzadmin/system/summary`, `/bzadmin/system/cpu`, `/bzadmin/system/runtime` | `GET /bzadmin/system`, in any format |
| `GET /bzadmin/system/properties` | `GET /bzadmin/system?view=properties` |
| `GET /bzadmin/application/summary` | `GET /bzadmin/application`, in any format |
| `GET /bzadmin/service/match` | `GET /bzadmin/services/lookup` |

With Berlioz mapped by prefix, the same paths are under `/html/` and `/xml/`.

**Fallback login.** Clients that retry wrong credentials quickly may now receive `429`. Behind a proxy,
make sure the container applies the forwarded headers, otherwise every client shares the proxy's limit.

See [upgrading and rollback](../guides/upgrading.md).

## Known limitations

- Java 11 and Jetty 10 are the reference test environment; Tomcat 9 and newer JDKs are not qualified.
- Includes of admin pages are denied. Avoid using admin URLs as container error pages; container-generated
  error responses can have different headers, and an error dispatch to an operation can execute it for an administrator.
- With container BASIC authentication, a request other than GET without credentials receives a Berlioz
  error document without the 401 challenge, unless the host declares an
  [error page for 401](../access.md#error-page-for-401).
- JCache keys cannot be listed. EHCache 2 byte sizes and statistics reset are unavailable. Two registered
  JCache managers sharing a URI have no statistics. Cache keys are shown without redaction.
- Log contents and service generator parameters are displayed as supplied; they must not contain secrets.
- XSLT documentation describes source declarations: it does not evaluate `use-when` or load used packages.
- Kickstart may log a warning for XML responses when it selects the fallback stylesheet because
  `WEB-INF/xslt/xml/bzadmin.xsl` is absent.

See [installation](../getting-started.md), [security and support](../../SECURITY.md), and
[troubleshooting](../guides/troubleshooting.md).
